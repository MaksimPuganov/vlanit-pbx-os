# Спека: CI-сборка релизов и GPG-подпись (идея #11)

Реализовано в 1.2.6 (коммиты `d9f3662`, `a34d95a`, `a6d62e0`).

## Корень изменения

Релизы 1.2.0–1.2.5 собирались локально и выкладывались вручную
(`gh release create` с рабочей машины). Риски: расхождение «что в git» и
«что в ISO», неподтверждаемое происхождение артефакта, отсутствие защиты
контрольных сумм от подмены. Полевое требование (идея #11, фидбек
Alexander Kuznetsov): тег не меняется, релиз собирает CI, checksums подписаны.

## Решение (as-built)

Что · значение · где · как проверяется:

- Триггер релиза · push тега `v*` · `.github/workflows/build-iso.yml`
  (`on: push: tags`) · релиз на GitHub создан с тем же тегом
  (`gh release create --verify-tag`).
- Источник сборки · коммит, на который указывает тег (checkout по событию
  push) · тот же workflow · `--verify-tag` падает, если тега нет на remote.
- Сборка ISO · `make iso` внутри job (образ `vlanit-build:1.1`,
  привилегированный контейнер) · workflow шаг «Сборка ISO» · артефакт
  содержит ISO + `.sha256` + `.sha256.asc`.
- Подпись checksums · detached GPG-sign ключом релиза
  (`scripts/sign-release.sh`) · workflow шаг «Подпись контрольных сумм»;
  приватный ключ — GitHub Secret `RELEASE_GPG_PRIVATE_KEY` ·
  `gpg --no-default-keyring --keyring rootfs/etc-vlanit-release.pub
  --verify <f>.sha256.asc` → «Действительная подпись VLANit PBX OS Release».
- Публичный ключ релиза · `rootfs/etc-vlanit-release.pub` (ed25519,
  отпечаток `2DAC A38E 333C 55FA 5A01 9BC4 610F F753 8C19 4CB4`) · в git
  и внутри образа ОС · тот же gpg --verify.
- Ручной запуск · `workflow_dispatch`, параметр `release: true/false`
  (артефакт без публикации / с публикацией) · workflow · run вручную.
- Права на dist · ISO создаются контейнером от root; перед подписью
  `sudo chown -R $USER dist` (без этого gpg: Permission denied,
  исправлено в `a6d62e0`) · workflow · зелёный шаг подписи.

Ключ релиза — тот же, что подписывает OTA-пакеты (`build-update-package.sh`,
GNUPGHOME `~/.vlanit-release-gnupg` локально): одна цепочка доверия на
OTA и на установочные ISO.

## Отклонённые альтернативы

- Подпись ISO целиком вместо `.sha256` — подписываем checksums: подпись
  маленькая, проверка у клиента дешёвая, ISO передаётся как есть.
- Cosign/Sigstore вместо GPG — внутренний ключ ed25519 уже существовал
  для OTA, GPG — стандарт de facto для дистрибутивов (Debian-подобная
  модель подписи Release-файлов).
- Сборка релиза локально с последующей выкладкой — отклонена самой
  постановкой идеи #11.
