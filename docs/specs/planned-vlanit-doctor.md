# Спецификация (плановая): `vlanit-doctor` — диагностический скрипт установленной ОС

Статус: **запланировано** (задача, реализация не начата).
Целевая версия: 1.3.0 (после 1.2.4).

## Цель

Одна команда на установленном устройстве, которая отвечает на вопрос
«всё ли корректно работает?» — для администратора в поле и для поддержки
при разборе обращений. Сводный отчёт по здоровью системы + конкретные
инструкции по устранению найденного.

## Контекст

Сейчас диагностика распределена: 33 проверки живут в тест-агенте
(`rootfs/vlanit-test-agent.sh`), который активируется только по
`VLANIT_TEST=1` в kernel cmdline и пишет на serial-порт. В поле такого
механизма нет — инженер вручную собирает состояние из десятка команд
(см. Runbooks wiki). `vlanit-doctor` переносит проверки агента в
пользовательский инструмент.

## Объём проверок (черновик, наследуется от тест-агента 1.2.4)

| Группа | Проверки |
|---|---|
| Система | hostname, `/etc/timezone`, timesyncd (синхронизация), apt sources (security), unattended-upgrades |
| Диски и ФС | Btrfs subvolumes смонтированы, место на System/Data, снапшоты доступны |
| Сеть | IP-адрес получен, gateway, DNS-resolve, WireGuard (если включён): интерфейс, ключи, последняя handshakes |
| Firewall | nftables активен, policy drop присутствует, ожидаемые порты слушаются |
| SSH и доступ | host-ключи, ssh.service активен, PermitRootLogin=no, fail2ban жив |
| MikoPBX | quadlet-служба активна, образ нужной версии, контейнер healthy, веб отвечает (https, внешний IP), API-логин (если пароль известен — только код возврата, без секрета), SSH_PORT=23 |
| Журналы | journald persistent, записи прошлой загрузки читаются |
| Обновления/бэкап | свежесть security-обновлений (apt list --upgradable), наличие снапшотов pre-update |

## Интерфейс

```
vlanit-doctor              # полный отчёт
vlanit-doctor --quiet      # только код возврата (0/1) для скриптов
vlanit-doctor --fix-hints  # с командами-исправлениями под каждой проблемой
vlanit-doctor --json       # машиночитаемый вывод (для поддержки/мониторинга)
```

Вывод: таблица/список по группам, каждый пункт `OK / FAIL / SKIP (не применимо)`
с однострочной диагностикой. Код возврата: 0 — всё зелёное, 1 — есть FAIL.

## Нефункциональные требования

- Без сетевых обращений наружу (кроме DNS-resolve и NTP-проверки — опция);
  веб/API MikoPBX — только на локальные адреса устройства.
- Секреты не выводятся и не логируются (проверка API-логина — по коду
  ответа; пароль не отображается).
- Время выполнения < 30 с; root не обязателен для `--quiet`-режима чтения
  (часть проверок деградирует в SKIP).
- Идемпотентность и безопасность: скрипт ничего не меняет (read-only).

## Реализация (наметка)

- Источник проверок — рефакторинг `vlanit-test-agent.sh` в общую библиотеку
  (`/opt/vlanit/lib/checks.sh`), которую используют и агент, и `vlanit-doctor`
  (один источник правды, регрессия тестами покрывает оба).
- Место: `/usr/local/sbin/vlanit-doctor` (Golden Image).
- Журнал: печать в stdout + опционально `--log /path`.

## Проверка (когда будет реализовано)

- Unit-тесты на библиотеку проверок (моки команд).
- Интеграция: прогон в QEMU после установки (расширить агента:
  `vlanit-doctor --quiet` вместо части ручных проверок).
- Ручной прогон на железе с заведомо сломанными компонентами
  (остановлен mikopbx, выключен nftables, снят WG).
