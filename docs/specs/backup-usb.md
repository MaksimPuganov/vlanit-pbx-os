# Спецификация: локальный бэкап на USB (1.2)

Статус: **реализовано** (1.2.0, подтверждено тестом Т9 на 1.2.1).

## 0. As-built

- Архив: `vlanit-backup-<hostname>-<ts>.tar.zst` — каталог с
  `data.tar.zst` (cf + storage), `system-etc.tar.zst`, `SHA256SUMS`,
  `backup-manifest.json`.
- Остановка контейнера — с **повторными попытками** (6 × 10 с): `systemctl stop`
  в момент транзакции запуска контейнера (firstboot стартует его с
  `--no-block`) конфликтует и отменяется; без ретраев бэкап падал на свежей
  загрузке.
- Восстановление вручную: `systemctl stop mikopbx`,
  `tar -C / --zstd -xf <backup>/data.tar.zst`, `systemctl start mikopbx`.
- В тесте Т9 USB-носитель — 3 ГБ (на 2 ГБ запас по месту был критичным:
  storage содержит offload-файлы MikoPBX ~1.2 ГБ).

## 1. Команда

`vlanit-backup [mountpoint]` — без аргумента сканирует USB-носители
(как `vlanit-update`), требует подтверждения.

## 2. Состав бэкапа

`vlanit-backup-<hostname>-<ts>.tar.zst` на целевом USB:

- `cf/` — копия `/var/spool/mikopbx/cf` (остановка контейнера обязательна
  для согласованности SQLite);
- `storage/` — копия `/var/spool/mikopbx/storage`;
- `system-etc.tar` — `/etc` (wireguard, networkd, ssh, quadlet, fstab-копия);
- `backup-manifest.json`: версии ОС/АТС, hostname, дата, список файлов
  с SHA256.

## 3. Процесс

1. Проверка свободного места на USB (нужно ≥ размера данных + 10%).
2. `systemctl stop mikopbx` (с таймаутом 90 с; при недожде — ошибка и выход).
3. `tar --zstd` трёх составляющих в tmp на USB (атомарность: пишем во
   временный файл, затем rename).
4. Запись manifest, `sync`.
5. `systemctl start mikopbx`; health-check до 5 минут.
6. При ошибке на любом шаге после остановки контейнера — контейнер
   гарантированно стартует обратно (trap).

## 4. Восстановление (не автоматизируется в 1.2)

Документируется в troubleshooting: остановить контейнер, распаковать
`cf/` и `storage/` поверх существующих subvolumes, при необходимости
развернуть system-etc. Автоматическое восстановление — отдельная
спека после первых реальных кейсов.

## 5. Критерии приёмки

- Бэкап на тестовом устройстве создаётся, размер адекватен;
- контейнер после бэкапа в healthy-состоянии;
- файлы из cf/storage читаются и содержат ожидаемые данные;
- Т9 (QEMU): backup → модификация данных → восстановление вручную по
  инструкции → MikoPBX healthy с исходной конфигурацией.
