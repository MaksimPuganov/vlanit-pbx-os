# Спецификация: 1.2.4 — системная интеграция и харденинг (пункты 1, 3, 6, 7, 8)

Статус: **реализовано** (1.2.4, все Т1–Т9 PASS, агент 33 проверки)..
Источник: полевые тесты 1.2.2 (A. Kuznetsov). Диагностика выполнена,
корневые причины подтверждены в коде.

## Пункт 1 — вход в установленную систему (критично)

### 1a. Отсутствует программа `login`

- **Корень (подтверждено):** пакет `login` (Priority: required, /bin/login)
  отсутствует в Golden Image — mmdebstrap в режиме явного списка пакетов его
  не подтянул. getty не может аутентифицировать пользователя.
- **Фикс:** добавить `login` в `GOLDEN_PACKAGES` (зависимости PAM установятся
  автоматически).
- **Проверка:** агент `bin-login-present` (`test -x /bin/login`).

### 1b. SSH host-ключи не генерируются

- **Корень (подтверждено по unit-файлу):** `sshd-keygen.service` имеет
  `ConditionFirstBoot=yes`; `vlanit-firstboot` раньше инициализирует
  machine-id, к моменту проверки условия «первая загрузка» уже ложь → ключи
  не создаются никогда (ключи также удаляются при очистке Golden).
- **Фикс (as-built):** `ssh-keygen -A` в `vlanit-firstboot.sh` перед включением
  ssh. При реализации выявлен второй корень: `ssh.service` падает на старте
  без ключей и уходит в **rate limit systemd** («Start request repeated too
  quickly»), поэтому после генерации обязательны `systemctl reset-failed
  ssh.service` + безусловный `restart` (`try-restart` не трогает failed-юниты).
  Вариант дроп-ина sshd-keygen отклонён: лечил бы симптом чужого юнита.
- **Проверка:** агент `ssh-host-keys` (verbose-диагностика в AGENT_LOG).

## Пункт 3 — firewall по умолчанию (ADR-0003)

- **Позиция:** порты АТС (SIP/RTP/веб) закрывать нельзя — телефония должна
  быть достижима. Риск — управляющие порты (SSH 22, WireGuard 51820)
  смотрят наружу; fail2ban реактивен.
- **Фикс (as-built):** `/etc/nftables.conf` (Golden Image), служба
  `nftables.service` включена. `table inet filter`: `input policy drop`;
  разрешены: loopback, established/related, ICMP, **QEMU slirp 10.0.2.0/24**
  (правило для автотестов в user-mode сети; на железе безвредно — RFC1918),
  tcp 22, udp 51820, tcp 80/443, tcp 5060/5061, udp 5060 и 10000–10800.
  `forward policy drop` + разрешение только для wg0 (road-warrior).
  Инструкция ограничения по подсетям админа — в README и комментарии
  к файлу.
- **Проверка:** агент `nft-policy-drop` (`nft list ruleset | grep "policy drop"`).

## Пункт 6 — персистентность журналов

- **Корень:** journald `Storage=auto`; каталога `/var/log/journal` в Golden
  нет → журналы в `/run/log/journal` (tmpfs), теряются при ребуте.
- **Фикс (as-built):** `mkdir -p /var/log/journal` в Golden;
  `/etc/systemd/journald.conf.d/01-vlanit.conf`: `Storage=persistent`,
  `SystemMaxUse=200M` (защита раздела System 40 ГБ).
- **Проверка:** агент `journal-persistent` — после reboot-фазы
  `journalctl -b -1 -n 1` возвращает записи прошлой загрузки.

## Пункт 7 — лимиты контейнера

- **Корень:** quadlet без `PidsLimit` → podman-дефолт 2048; стоп через
  podman имеет собственный таймаут 10 с, MikoPBX корректно гасит сервисы
  дольше.
- **Фикс (as-built, `quadlet/mikopbx.container`):** `PidsLimit=4096`,
  `TimeoutStopSec=120`. `MemoryMax` осознанно не задан.
- **Проверка:** агент `pids-limit` — `podman inspect … PidsLimit`=4096.

## Пункт 8 — кнопка питания

- **Корень:** logind по умолчанию: короткое нажатие → poweroff; для
  АТС-апплаенса случайное нажатие роняет телефонию.
- **Фикс (as-built):** `/etc/systemd/logind.conf.d/01-vlanit.conf`:
  `HandlePowerKey=ignore`, `HandlePowerKeyLongPress=poweroff` (>5 с — штатное
  выключение). Вариант `suspend` отклонён: «спящая» АТС не принимает звонки.
- **Проверка:** агент `handle-power-key` — `HandlePowerKey` = "ignore" (busctl).
