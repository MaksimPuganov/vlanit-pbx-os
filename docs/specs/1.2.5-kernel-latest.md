# Спека 1.2.5 — гарантия последнего ядра в образе

Issue: vlanit-com/vlanit-pbx-os#11

## Проблема (корень)

В опубликованной 1.2.4 ядро было `6.12.107`, хотя в trixie-security уже
вышло `6.12.116-1`. Два независимых корня:

1. **mmdebstrap очищает `/etc/resolv.conf`** в собираемом rootfs
   (оставляет висячий symlink на `/run/systemd/resolve/...`). Все
   последующие `apt-get update`/`full-upgrade` в chroot молча не
   резолвили хосты (`Temporary failure resolving`) — security/updates
   апгрейды никогда не применялись. Сеть при этом исправна.
2. **Порядок шагов**: блок security/updates-источников писался ПОСЛЕ
   `full-upgrade`, поэтому даже при рабочем резолве guard сравнивал
   установленную версию с неполным candidate.

## Решение (as-built)

Что · значение · где · как проверяется:

- sources (trixie + trixie-security + trixie-updates) пишутся ДО
  full-upgrade · `scripts/10-golden-rootfs.sh`, `scripts/20-live-rootfs.sh`
  · guard в сборке: `Installed == Candidate`.
- `resolv.conf` перед apt-операциями: `rm -f` висячего symlink +
  `cp -L /etc/resolv.conf` · оба скрипта · сборка падает, если apt
  не резолвит (update вернёт ошибку).
- Guard ядра после full-upgrade: `apt-get install --only-upgrade
  linux-image-amd64`, затем проверка `dpkg-query -W -f=\${Version}` ==
  `apt-cache policy Candidate`; несовпадение = ошибка шага · оба
  скрипта · лог сборки: `kernel installed=... candidate=...`.
- Старое ядро вычищается явно: purge всех `linux-image-<kver>` из
  `/lib/modules`, кроме newest (`sort -V | tail -1`), затем
  `autoremove` · оба скрипта · факты сборки `build/facts.json`
  (`kernel_version`), в 1.2.5 = `6.12.116+deb13-amd64`.
- Факты версий берутся с `sort -V | tail -1` (а не `head -1`) —
  защита от остатков старых ядер в манифесте.

Эффект: golden.tar.zst уменьшился с 471M до 322M (−149M: вычищено
ядро 6.12.107 + его модули/firmware).

## Отклонённые альтернативы

- Полагаться только на `apt-get autoremove` — не удалило старое ядро
  (пакет не был помечен orphaned; два ядра остались в rootfs).
- Проверять ядро только по метапакету `linux-image-amd64` — его версия
  совпадает с candidate всегда после `--only-upgrade`, не отражает
  фактический kernel image.
