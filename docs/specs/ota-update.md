# Спецификация: OTA-обновления (1.2)

Статус: **реализовано** (1.2.0, подтверждено тестом Т8 на 1.2.1). ADR-0001.

## 0. As-built: реализация и отличия от исходных решений

- Команды: `vlanit-update`, `vlanit-rollback` в `/usr/local/sbin` (Golden Image).
- Неинтерактивный режим: `VLANIT_ASSUME_YES=1 vlanit-update <пакет>`
  (нужен для скриптов и тестов; без него вне TTY команда отказывает с кодом 3).
- Пакет: `vlanit-update-<min_ver>+atsc<версия>-<дата>.tar` + `.asc`;
  сборка — `scripts/build-update-package.sh` (требует приватный ключ релиза
  в `~/.vlanit-release-gnupg`, вне репозитория; публичный ключ —
  `rootfs/etc-vlanit-release.pub`, зашит в ОС).
- Откат: вместо удаления subvolumes используется **переименование**
  (`@` → `@.rolled-back-<ts>`): смонтированный subvolume удалить нельзя.
- Онлайн-ветка apt упрощена: `apt-get update` + `unattended-upgrades`
  (security) без постраничного анализа; ошибка apt не откатывает обновление АТС.
- Поиск USB: только смонтированные носители с маской `vlanit-update-*.tar`;
  поиск ISO-метки носителя не используется.

## 1. Объём

- **Обновление АТС**: замена образа `localhost/vlanit/mikopbx:<ver>` на новый.
  Конфигурация (`/var/spool/mikopbx/cf`) и записи (`/storage`) сохраняются.
- **Обновление системы**: `apt-get upgrade` security/updates из репозиториев
  Debian (только при онлайн-канале и наличии сети).

Не входит: замена Golden Image целиком, обновление ядра/GRUB отдельными
пакетами вне apt, автоматическое применение.

## 2. Формат пакета обновления

Файл: `vlanit-update-<distro_ver>+atscver>-<ts>.tar` (tar, без сжатия — слои
уже сжаты) + рядом `*.asc` (detached GPG-подпись) + `manifest.json` внутри:

```json
{
  "schema_version": 1,
  "distro_version": "1.1.0",
  "target_min_version": "1.1.0",
  "mikopbx_image": "mikopbx-2026.6.114-amd64.tar.zst",
  "mikopbx_image_sha256": "<hex>",
  "signature_pubkey_fingerprint": "<fpr>",
  "created_at": "<ISO8601>"
}
```

Правила: пакет применим, если `VERSION_ID` устройства ≥ `target_min_version`;
обязательна проверка SHA256 образа до импорта и GPG-подписи до всего остального.

## 3. Доверие

- Пара ключей релиза генерируется выпускающим (хранится вне репозитория,
  публичный ключ — в `rootfs/etc-vlanit-release.pub`).
- Устройство проверяет detached-подпись `gpgv` с зашитым ключом;
  `manifest.json` обязателен — без него пакет отклоняется.

## 4. Команды

### `vlanit-update [путь-к-пакету]`

1. Без аргумента: сканирование смонтированных USB-носителей
   (`lsblk -o LABEL,MOUNTPOINT,TRAN`, метка `VLANIT_UPDATE` или любой tar,
   соответствующий маске `vlanit-update-*.tar`); при найденных нескольких —
   выбор из списка.
2. Опция `--online`: проверка URL релизов (из `/etc/vlanit/update.conf`),
   скачивание во временный каталог.
3. Проверка: подпись → manifest → совместимость версий → SHA256 образа.
4. Показ сводки (версии, объём, риск) и явное подтверждение `YES`.
5. Применение:
   - `vlanit-snapshot create pre-update` (read-only, на всё);
   - импорт образа: `zstd -dc | podman load`, тег `localhost/vlanit/mikopbx:<new>`;
   - смена тега в quadlet (`/etc/containers/systemd/mikopbx.container`),
     `systemctl daemon-reload`;
   - остановка контейнера, старт с новым образом;
   - онлайн-режим дополнительно: `apt-get update && apt-get -y upgrade`
     (только security, sources — штатные Debian; при сбое apt — предупреждение,
     но АТС остаётся обновлённой).
6. Health-check: баннер готовности в логах / HTTP до 5 минут; при таймауте —
   аварийное сообщение с указанием `vlanit-rollback`.
7. Журнал: `/var/log/vlanit-update.log`; секреты не пишутся.

Остановка обновления до пункта 5 не оставляет следов; после импорта образа
отмена возможна только через откат.

### `vlanit-rollback [имя-снапшота]`

1. Без аргумента: список снапшотов с пометкой `pre-update*`, выбор.
2. Предупреждение: контейнер будет остановлен, данные в `/cf` и `/storage`,
   изменённые после снапшота, будут потеряны; подтверждение `YES`.
3. `systemctl stop mikopbx`; удаление текущих subvolumes `@`, `@var_log`,
   `mikopbx-cf`, `mikopbx-storage`; `btrfs subvolume snapshot` из
   read-only снапшота в рабочие (rw); `reboot`.
4. После перезагрузки первичная проверка аналогична health-check OTA.

Требование: снапшоты pre-update не удаляются автоматически; команда
`vlanit-snapshot delete` — ручная.

## 5. Размещение в коде

- `snapshots/vlanit-update` — команда обновления;
- `snapshots/vlanit-rollback` — команда отката (использует `vlanit-snapshot`);
- `rootfs/vlanit-update.conf` — конфиг канала доставки (URL, интервал
  напоминаний; по умолчанию URL пуст = только USB).

## 6. Сценарии отказов

| Сценарий | Поведение |
|---|---|
| Подпись неверна | Отказ до изменений, код 2 |
| Версия устройства < min | Отказ с пояснением |
| SHA256 образа ≠ manifest | Отказ, образ не импортируется |
| Снапшот не создан | Обновление не начинается |
| Контейнер не стал healthy | Сообщение + инструкция отката, код 1 |
| Пропало питание mid-update | Идемпотентность: повторный запуск докачивает; при битом состоянии — откат из снапшота |

## 7. Критерии приёмки

- Обновление USB-пакетом: АТС новой версии, конфигурация сохранена.
- Откат: система возвращается к версии АТС из снапшота после reboot.
- Подписанный пакет с испорченным байтом отклонён.
- Офлайн-устройство обновляется с USB; онлайн — с `--online`.
- Тест Т8 (QEMU): update → health-check PASS → rollback → health-check PASS.
