# Спека 1.2.6 — исправления по полевому фидбеку 1.2.4

Источник: тест 1.2.4 в виртуалке (Alexander Kuznetsov, 2026-11-13).
Все шесть пунктов: корень → решение → проверка. Плюс замечание по sudo.

## 1. Системные файлы принадлежали uid 1000 (23 039 файлов, sudo мёртв)

**Корень:** сборка на хосте под обычным пользователем. mmdebstrap/tar
без root не могут назначить uid 0 — весь Golden Image уезжал с uid 1000.
Дополнительно `cp -a` из репозитория (файлы uid 1000 сборочной машины)
вносил чужое владение даже при контейнерной сборке.

**Решение:**
- `make iso` теперь ВСЕГДА запускает сборку в привилегированном
  build-контейнере (`docker run --rm --privileged ...`), цель `make image`
  собирает образ сборки. Прямой запуск build.sh на хосте — только осознанно.
- После `cp -a` VLANit-компонентов: `chown -R root:root`.
- Guard перед упаковкой golden/squashfs: `find -uid +999 -o -gid +999`
  → любой файл с uid/gid ≥ 1000 обрывает сборку с диагностикой.
- Установщик: без изменений (tar -p как root сохраняет владение архива).

**Проверка:** агент `files-root-owned` (`find / -xdev -uid 1000 -not -path
'/home/*'` == 0) и `sudo-works` (sudo root-owned, setuid-бит).

## 2. Тестовое правило 10.0.2.0/24 accept в nftables образа

**Корень:** `rootfs/etc-nftables.conf` содержал правило «для автотестов»;
в сети клиента с той же адресацией экран фактически открыт.

**Решение:** правило удалено из образа. QEMU-автотесты не пострадали:
управление открыто портами (22/tcp, 51820/udp), а хост-пробros
hostfwd идёт через slirp с адресов 10.0.2.x — но агент проверяет с
самой гостевой системы (loopback/gateway-доступ), hostfwd к гостю
попадает в `ct state established,related` + порты.

**Проверка:** агент `nft-no-testnet` (`! nft list ruleset | grep 10.0.2.0/24`).

## 3. Пароль веб-админа АТС из мастера не принимался

**Корень (два слоя):**
1. Блок `VLANIT-ENV` вставлялся после `[Service]` в quadlet. Quadlet
   передаёт `Environment=` в контейнер (`--env`) ТОЛЬКО из секции
   `[Container]`; из `[Service]` переменная остаётся окружением
   systemd-юнита. Подтверждено `-dryrun` генератора quadlet 5.4.2.
2. Пароль без кавычек ломался при пробелах/спецсимволах
   (dryrun: значение с пробелом обрезалось).

**Решение:**
- Вставка блока после `[Container]` (deploy.sh и vlanit-provision,
  идемпотентно — маркеры сохранены, старые установки при повторном
  provisioning'е переезжают корректно).
- Кавычирование значений с пробелами/кавычками (systemd-формат) в обоих
  писателях; firstboot и тест-агент снимают окаймляющие кавычки при чтении.

**Проверка:** агент `atc-env-in-container` (env внутри контейнера) +
`mikopbx-api-login` реальным паролем из quadlet. В upstream-проблеме
(#10, reboot-api-login WARN) изменений нет.

## 4. Контейнер останавливался за 10 секунд (stoptimeout=10)

**Корень:** `TimeoutStopSec=120` был в `[Service]` — это таймаут systemd
на остановку юнита, а не контейнера. Контейнеру задаётся
`--stop-timeout` из `StopTimeout=` в `[Container]` (дефолт 10 с).

**Решение:** `StopTimeout=120` в `[Container]` quadlet-шаблона.
Подтверждено dryrun: `--stop-timeout 120` в podman run.

**Проверка:** агент `atc-stop-timeout` (`podman inspect StopTimeout == 120`).

## 5. ssh.service падал 6 раз до генерации host keys

**Корень:** ключи генерировал firstboot, но ssh.service стартует раньше
firstboot → 6 неудач (rate limit), потом рестарт.

**Решение:** drop-in `/etc/systemd/system/ssh.service.d/00-keygen.conf`
(`ExecStartPre=/usr/bin/ssh-keygen -A` — в Debian 13 ssh-keygen в /usr/bin,
пакет openssh-client) — ключи есть ДО первого старта sshd; firstboot-логика
осталась как идемпотентная подстраховка.
Ключи по-прежнему НЕ в Golden Image (уникальность на устройстве).

**Проверка:** агент `ssh-clean-start` (NRestarts==0, ssh active).

## 6. Часовой пояс UTC, мастер не спрашивал

**Корень:** TZ_NAME задавался только через autoinstall.yaml (default UTC);
TUI-мастер не спрашивал.

**Решение:** экран 4 TUI: ввод IANA-часового пояса, дефолт
Europe/Moscow, валидация по /usr/share/zoneinfo; пояс добавлен в сводку
экрана 5. Путь применения без изменений (deploy.sh: /etc/timezone +
/etc/localtime). autoinstall-тесты переведены на Europe/Moscow.

**Проверка:** агент `timezone-set` (/etc/timezone непуст) + фактическое
значение в тест-конфиге Europe/Moscow.
