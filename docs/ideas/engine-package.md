# Идеи развития VLANit PBX OS (бэклог, НЕ в работе)

Источник: полевой фидбек (Alexander Kuznetsov), тест 1.2.4, 2026-11-13.
Тема: сделать ОС независимой от конкретной АТС внутри («пакет движка»).
Главные по приоритету: **1, 2, 4** (решение о взятии — за владельцем продукта).

## 1. Слот АТС принимает «пакет движка»

Не один фиксированный контейнер MikoPBX, а папка Quadlet-юнитов:
pod + контейнеры + тома. Установщик и OTA работают с любым движком,
реализующим контракт (п. 2).

## 2. Контракт пакета движка

Поля пакета, которые читает ОС:

- порты (SIP/веб/SSH) и диапазон медиа (RTP);
- тома (что бэкапить, что персистентно);
- команда проверки здоровья;
- время на остановку (StopTimeout);
- лимит процессов;
- пути бэкапа;
- хуки: до бэкапа / после восстановления;
- файл версии пакета.

Тогда `vlanit-update`, `vlanit-rollback`, `vlanit-backup` — движко-нейтральны.
Формат: `engine.yaml` в корне пакета + каталог `quadlet/` с юнитами.

## 3. Сеть движка на мосту

У pod движка свой адрес в локальной сети (мост), firewall хоста остаётся
снаружи АТС. Отказ от `network_mode: host` → проще изоляция и политики.

## 4. Здоровье = ответ по SIP, не живой процесс

Проверка здоровья движка — SIP-ответ (OPTIONS/REGISTER), а не «процесс жив»:

- перезапуск контейнера при отказе проверки;
- автооткат OTA-обновления, если проверка падает в первые N минут
  (guard window после update).

## 5. Голосовой профиль хоста

Профиль настройки ОС под телефонию:

- размеры UDP-буферов (net.core.rmem_max/wmem_max);
- conntrack выключен/ограничен для диапазона медиа (NOTRACK);
- синхронизация времени (chrony вместо timesyncd?);
- CPU governor = performance.

## 6. Секреты через Podman secrets

Секреты создаются на первой загрузке устройства (свои на каждом),
передаются контейнеру как Podman secrets; в quadlet-юнитах секретов нет
(сейчас WEB_ADMIN_PASSWORD в файле с chmod 600 — шаг в ту же сторону).

## 7. Образы по digest + SBOM

- образы движков поставляются по digest с установочного носителя;
- на каждый образ — SBOM и предложение исходников (движки под GPL).

## 8. Интеграционный тест: звонок

Два SIP-пользователя регистрируются и разговаривают через установленный
образ в QEMU (sipp/pjsip). Медиа-путь RTP проверяется end-to-end.

## 9. Журналы пакета

- срок хранения журналов — настройка пакета движка;
- одна команда собирает логи всех контейнеров пакета (`vlanit-logs`).

## 10. Сборка под arm64

Портирование сборочной системы и golden rootfs на aarch64 (ARM-платы).

## 11. Правило релизов — РЕАЛИЗОВАНО (1.2.6)

- тег и файлы релиза не меняются после публикации;
- каждый релиз собирает CI из запушенных исходников — push тега `v*`
  триггерит workflow build-iso, релиз публикуется с этим тегом
  (`--verify-tag`), ручной запуск сохранён как workflow_dispatch;
- контрольные суммы подписаны GPG-ключом релиза
  (`scripts/sign-release.sh`, pub — `rootfs/etc-vlanit-release.pub`,
  приватный ключ — GitHub Secret `RELEASE_GPG_PRIVATE_KEY`);
  проверка: `gpg --no-default-keyring --keyring rootfs/etc-vlanit-release.pub
  --verify <file>.sha256.asc`.

## 12. Роль установки «edge»

Вторая роль: та же ОС, но с пакетом прокси и публичным адресом
(точка входа для fleet-подключений).

---

### Заметки по оценке взятия (1, 2, 4)

- **1+2** — естественное развитие текущей архитектуры (quadlet уже есть),
  но требует абстракции над `mikopbx.service` именами в firstboot/OTA/
  backup/health-check. Разумный целевой релиз: 1.4.0.
- **4** — SIP-проверка здоровья требует SIP-стека на хосте (sipsak/pjsua) или
  проверки через API движка; автооткат защитит полевые обновления.
  Можно взять раньше, движко-специфичная часть — команда проверки из
  контракта пакета (п. 2).
